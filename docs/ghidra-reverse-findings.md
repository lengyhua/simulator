## 2. 逐环节实证

### 2.1 f₀：5 项高斯 + c（FUN_004787f8 原子循环 0x47888d–0x478945）【汇编】

```
对每个原子 j（记录基址 Self+0x1390+96j）：
  FLD [rec+8]   ; b1
  FCHS; FMUL s² ; -b1·s²
  CALL exp; FMUL [rec+0]    ; × a1
  …（b2/a2 @+0x18/+0x10，b3/a3，b4/a4，b5/a5 同构）…
  FADD [rec+0x50]           ; + c
  FSTP f₀
```

即 **f₀ = Σ\_{k=1..5} a_k·e^{−b_k s²} + c**，s² = 1/(4d²)（见 2.3）。记录 96 B = 8 B ShortString 名 + 11 double 交错（a1 b1 … a5 b5 c）。

- 与 Factor.dat 字节布局、项目 `factor_data.ts` **完全一致**（`scripts/gen_factor_dat.py --check` 已另行验证）。
- help §3(4) 写「i from 1 to 4, 9 data」是**过时文本**；help 自己引用的 Waasmaier & Kirfel (1995) 正是 5 高斯式。

### 2.2 色散 F′/F″（粉末 0x47894a–0x47899a；single 0x47c7f2–0x47c842）【汇编·双路径同构】

F′F″ 复选框（Self+0x398）开时（**粉末路径**，0x47894a 起）：

```
MOV EAX,[EBX+0x398]; CALL [EDX+0xc4]      ; get_Checked
FLD [ESP+0x10]                             ; f₀
FADD [EBX+EAX*8+0x3958]                    ; f₀+f′   （EAX=2j → 0x3958+16j = f′）
FLD float [0x478d18]                       ; 0.5
FMUL [EBX+EAX*8+0x3960]                    ; 0.5·f″  （0x3960+16j = f″）
FMUL [EBX+EAX*8+0x3960]                    ; 0.5·f″²
FLD [ESP+0x10]; FADD [EBX+EAX*8+0x3960]    ; f₀+f″
FDIVP; FADDP                               ; (f₀+f′) + 0.5f″²/(f₀+f″)
FSTP [ESP+0x10]
```

**single 路径**（0x47c7f2–0x47c842）与此**逐指令同构**（常量池换为 0.5@0x47ca84）：`FLD f₀; FADD f′; FLD 0.5; FMUL f″; FMUL f″; FLD f₀; FADD f″; FDIVP(0x47c83a); FADDP`。

**f = f₀ + f′ + 0.5·f″²/(f₀ + f″)** —— 实数标量，无复数。f′/f″ 槽位由装载器 FUN_0047907c 实证：pair 低/高双字写 0x3958+16j / 0x3960+16j（见 §2.9）。

三者对照（以 Ce：f₀≈52, f′=−1.88, f″≈9.7 计）：

| 来源               | 公式                                 | 数值  | 与精确模差 |
| ------------------ | ------------------------------------ | ----- | ---------- |
| 本代码             | f₀+f′+0.5f″²/(f₀+**f″**) | 50.88 | −0.33%    |
| help (5)           | f₀+F′+0.5F″²/(f₀+**F′**) | 51.06 | +0.02%     |
| 精确               | √((f₀+f′)²+f″²)                | 51.05 | 0          |
| 项目 web（复数式） | 同精确式                             | 51.05 | 0          |

→ 代码分母用 f″ 是**独立于 help 的实现细节**（疑似作者笔误，但保真优先应复现）。fidelity 模式需按此式。

### 2.3 s² 与 DW（粉末 0x47883c–0x47885e、0x4789dd–0x478a05；single 0x47c6e4–0x478706、0x47c885–0x47890f）【汇编】

single 路径 s²（0x47c6e4–0x47c706）：

```
FLD float [0x47ca7c](=2.0); FMUL d[i]; FLD 2.0; FMUL d[i]; FMULP   ; (2d)²
FDIVR float [0x47ca80](=1.0)                                        ; s² = 1/(4d²)
FSTP [ESP+0x20]
```

DW（Thermal 复选框 Self+0x36c 开，single 路径 0x47c885–0x47c8b4）：

```
FLD [0x440+40j]; FCHS; FMUL s²; CALL 0x004029c4(exp)   ; e^{−B s²}（B = 原子记录 +0x20）
FMUL [ESP+0x10]                                         ; × 完整 f_eff（含 F′ 与 0.5f″²/(f₀+f″) 项）！
FMUL [0x420+40j]                                        ; × occ
```

粉末路径同构（0x478a05 起同样 `FLD B; FCHS; FMUL s²; CALL exp; FMUL f_eff; FMUL occ`）。

- **DW 作用对象 = 完整 f_eff（含 F′ 与 0.5f″²/(f₀+f″) 项）**；help §3(3)「f=f₀·exp(−Bsin²θ/λ²)」（只作 f₀）与 IT Vol. C 惯例均只作 f₀，项目现行约定作 (f₀+f′) —— **代码三者中最宽**。
- B 是逐原子参数（原子记录 0x440+40j，即几何记录 +0x20）✓ 与 GUI 实测一致。
- `CALL 0x004029c4` 紧跟 `FCHS; FMUL s²` 且返回被 `FMUL a_k` 消费 → **FUN_004029c4 = exp**（x87 约定 ST(0) 传参）；同理 FUN_004029b4 = fcos、FUN_004029dc = fsin（φ 的 cos/sin）。

### 2.4 相位与结构因子（0x47899b–0x4789d8、0x478a01–0x478aad）【汇编】

```
φ = 2π( h·x_j + k·y_j + l·z_j )            ; 2π(extended)@0x478d1c
h,k,l = int 数组 @ Self+0x3fb0+12i
x,y,z = 原子记录 +8/+0x10/+0x18；occ = +0
Re += f_eff·occ·cos φ ;  Im += f_eff·occ·sin φ
|F|² = Re² + Im²                            ; → Self+0x4a4ac+4i
```

与 help §2(2) `F=Σf_j·exp(2πi(hx+ky+lz))` 一致。**注意 f_eff 为实数**（色散已折成标量），非复数求和。

### 2.5 |F|² 硬阈值 0.01（0x478ad6–0x478b09）【汇编】

```
for i=1..count: if (0.01 ≤ |F|²[i]) keep else |F|²[i]=0
```

常量 0.01 为 **80 位 extended**（0x478d28，raw `0ad7a3703d0ad7a3f83f`）。粉末路径在装箱前统一执行；single 路径不清零，但**表格显示过滤同样是 |F|²≥0.01**（0x47c648，extended 0.01）。

### 2.6 hkl 枚举与 2θ（FUN_004780b4）【汇编】

```
h_max = f(2a/λ), k_max = f(2b/λ), l_max = f(2c/λ)   ; f = FUN_004271c0（Round 微调）
θ_max = π/2 → sin=1 → d_min = λ/2                    ; 0x47828e–0x4782a7
for h∈[-h_max..h_max], k, l（全枚举，(0,0,0) 除外）:
    d = V/√(三斜通用式)                               ; V=abc√(1−cos²α−cos²β−cos²γ+2cosαcosβcosγ)
    if d_min < d: count++（≥12000 时回退，即上限 12000）; 存 d[i], hkl[i]
选择排序：按 d 降序（等价 2θ 升序），d 与 hkl 联动交换
2θ[i] = Round( 2·arcsin((λ/2)/d)·(180/π)·1000 ) / 1000   ; 毫度，0x47875c–0x4787b5
```

- **mult 隐含**：等价反射（如 (100)/(010)/(001)/(−100)…）逐条入列，装箱时自然累加 → 粉末 mult 不需要显式乘法器。
- 排序方向：d 降序（FCOMP+JBE 判据实证）。
- h/k/l 上限函数 FUN_004271c0 = `Round(x)` 后按 `Frac(x)<0.5` 再 −1 的微调（边界取整风格，不影响物理）。

### 2.7 高斯峰形与装箱（FUN_00479450 + FUN_004787f8）【汇编】

```
FUN_00479450: q = StrToFloat(EditQ)                      ; Self+0x354
  for i=1..399:
     x = (100.0 − 200.0) + i·0.01                        ; = 0.01(i−200)+100，即距峰心 2θ 偏移(度)
     shape[i] = exp( −(x−100.0)² / (2.0·q·q) ) / (q·√(2π))
  max = max(1.0, shape[1..399]);  norm = 10000.0/max
  shape[i] *= norm                                       ; → shape[200] = 10000.0
装箱（PeakShape 复选框 Self+0x368 开）：
  for 每个 |F|²[i] ≥ 0.01 的反射:
     for k=1..399:
        bin = Round(2θ[i]·100) + k − 200
        if 1 ≤ bin ≤ 10000: Pattern[bin] += shape[k]·|F|²[i]/shape[200]
```

**PeakShape 读点定案（2026-10-19，字节级实读）**：PeakShape 复选框
（`Self+0x368`）的 `mov EAX,[EBX+0x368]` 在全 `.text`（0x400–0x7c200）中
**仅有一处**调用点 `0x478b1f`，位于 `FUN_004780b4`（hkl 枚举 + 装箱函数）
内——**不在** `.xrd` 写出器 `FUN_0047a724` 中。即：装箱模式（高斯 vs δ 棒）
由 `FUN_004780b4` 根据复选框状态预先决定，`.xrd` 写出器只负责把已装箱的
`Pattern[]` 数组逐行写出，本身不读该复选框。这与 web 侧 `pipeline.ts`
现行结构一致（`q=0` 时 δ 棒、`q>0` 时高斯装箱，均在 `gaussianBroaden`
统一处理，由调用方传入 `params.usePeakShape ? params.q : 0`）。

- 常量：2.0@0x479584、0.01@0x479588、2π@0x479594、10000.0@0x4795a0；shape[200]@Self+0x56350。
- **净效果**：每个反射以峰高 |F|²、FWHM=2.355q 度的高斯落入 0.01°/bin 的网格；`1/(q√(2π))` 前因子与 max 归一化、÷10000 相互抵消——**代码级证实项目 #9**（峰高 = I_hkl，与 q 无关的归一化处理自洽）。

### 2.8 Lp 因子（粉末 0x478c25–0x478cfe；single 0x47c97e–0x47ca77）【汇编·双路径 cos(2θ) 实锤】

L-P 复选框（Self+0x364）开时，对每个 bin i=1..10000（粉末）：

```
if Pattern[i] > 0:                                        ; 阈值 0.0@0x478d0c
   θ = (i/100.0)/2.0 × π/180                              ; 弧度；100.0@0x478d34, 2.0@0x478d10, π@0x478d38, 180@0x478d44
   Pattern[i] = (1 + cos²(2θ))·Pattern[i] / (sin²(θ)·cos(θ))
```

即 **Lp(2θ) = (1+cos²2θ)/(sin²θ·cosθ)**，与 help §4 一致（RTF 转码后的 "sin2 sin" 即 sin²θ·cosθ）。

**cos(2θ) 的指令级证明**（粉末 0x478c7d–0x478ca4）：θ 算出后 `FLD 2.0; FMUL θ; CALL fcos` **做两次**再 FMULP 平方——即 cos²(2θ) 而非 cos²θ。

**single 路径同式**（0x47c97e 起）：`λ/2 < d[i]` 过滤（0x47c9b1–0x47c9c1，JNC 跳过）；θ = arcsin(λ/2d)（`FUN_00427170`，m80 传参，0x47c9e1）；随后 `FLD 2.0; FMUL θ; CALL fcos` ×2（0x47c9eb/0x47c9ff）→ cos²(2θ)，`CALL fsin` ×2（0x47ca2a/0x47ca38）→ sin²θ，`CALL fcos` ×1 → cosθ；Lp **直接乘 |F|²**（逐反射），不清零、不装箱。

- 两个路径都只在复选框开时施加；θ 一律由几何反推，无查表。

> **111 归一表（全表除以 111 强度）跨 B 档比值** 闭合形式
> `I(N,B)/I(N,0) = exp(−2B(N−3)/(4a²))`，**15 个数据点最大残差
> 0.0076%，<0.1% 达标**。"2" 来自 |F|² 平方（f₀·e^(−Bs²) 进入 F，
> |F|² ∝ e^(−2Bs²)），"(N−3)" 来自 111 归一化基准（N_ref=3）在
> B 变化时自身也衰减 e^(−2B·3/(4a²))，跨 B 比值中体现为相对项
> (N−3)。非逐峰独立参数、非遗留缺陷。

**方法**：Fd 开 B 扫描 005(B=0)/004(B=0.4)/003(B=0.6)/002(B=0.8)，

即各表显示值 = `I_abs(N,B)/I_abs(111,B) × 100000`。

**定案**：

1. **111 归一表跨 B 档比值（005→004→003→002，各表全除以 111 强度）**：
   `I(N,B)/I(N,0) = exp(−2B(N−3)/(4a²))`
   其中 "2" = |F|² 平方（f₀·e^(−Bs²) 进入 F，|F|² ∝ e^(−2Bs²)）；
   "(N−3)" = 111（N_ref=3）归一化基准在 B 变化时自身衰减
   e^(−2B·3/(4a²))，跨 B 比值中体现为相对项。
2. **绝对口径（物理强度，无归一化）**：
   `I_abs(N,B) ∝ Lp(N)·mult(N)·[f₀(N)·exp(−B·N/(4a²))·(disp(N))]²`
   （disp = 色散修正，B 无关）。111 归一表显示值 = I_abs/I_abs(111)。
3. **s² 闭合形式**：`s² = N/(4a²) = 1/(4d²)`（立方晶系；

### 8.15 exp 桩精度裁决（2026-10-19，含当日勘误；web 引擎维持 Math.exp，不复刻桩）

> **⚠️ 勘误（2026-10-19 补记）**：本条初稿将桩描述为"`2^f` 的一阶线性
> 近似 `(1+f)·2^n`，单点相对误差 ~13%，B-scan 残差 21.22% 显著劣于
> Math.exp"——**该描述错误，已作废**。
>
> 勘误依据：直接读取 `CalcXRD.exe` 在 `0x4029c4` 的原始字节（pefile 实读，
> 文件偏移 `0x1dc4`），x87 指令序列为：
>
> ```
> D9 EA  FRNDINT(x·log2e)      → n
> DC E9  FMUL ST(1)
> D9 F0  FSCALE                → 2^n
> D9 E8  F2XM1(x·log2e − n)    → f = 2^(x·log2e−n) − 1  ← 关键指令
> DE C1  FSUBR ST(1)
> ```
>
> Ghidra 反编译伪代码写的是 `fscale(1 + f, n)`，其中 `f = f2xm1(...)`，
> **不是** `f = x'−n`（裸小数）。`F2XM1` 是 x87 硬件指令，精确计算
> `2^t − 1`（非一阶近似 `t·ln2`），故：
>
> ```
> f   = 2^(x·log2e − n) − 1
> 1+f = 2^(x·log2e − n)
> 2^n·(1+f) = 2^n · 2^(x·log2e − n) = 2^(x·log2e) = e^x   （数学上精确）
> ```
>
> 唯一残差来自 `FRNDINT` 的 80-bit 向偶取整舍入，量级 ~1e-14 相对误差，
> 在双精度 `Math.exp` 之下。
>
> 初稿误把 `f` 当成裸小数 `x·log2e − n`，漏掉了 `F2XM1` 这步，导致得出
> "桩单点误差 13.10%、B-scan 残差 21.22%"的结论。**该数字已作废**（见
> 下方数值裁决更新）。

**桩实现（勘误版）**（字节级确认，`CalcXRD.exe` 偏移 `0x1dc4`）：

```c
float10 exp_stub(x) {
    x' = x · 1.4426950408889634   // log2(e)
    n  = FRNDINT(x')             // x87 round-to-even
    f  = F2XM1(x' − n)          // x87 硬件 2^(x'−n) − 1（精确）
    return FSCALE(1 + f, n)      // x87 硬件 2^n · (1+f) = 2^n · 2^(x'−n) = e^x
}
```

**数值裁决（勘误版，`web/scripts/verify-exp-stub.ts`，2026-10-19）**：

| 模型                   | 15 点 B-scan cross-ratio（N−3 归一）最大残差 | 单点 vs Math.exp（x∈[−0.2,0]） | 判定                    |
| ---------------------- | --------------------------------------------- | -------------------------------- | ----------------------- |
| Math.exp（web 现行）   | **0.0076%**                             | —                               | ✅ legacy 有效口径      |
| 精确桩（f2xm1 还原）   | **0.0076%**（与 Math.exp 相同）         | 1.35e-14%（双精度量级）          | ✅ 与 Math.exp 不可区分 |
| 初稿误模型（无 f2xm1） | 21.22%（B=0.8, N=16）                         | 13.10%                           | ❌ 已作废               |

**结论（勘误版）/ web 引擎口径定案**：

- `structure_factor.ts` 维持 `Math.exp`（双精度原生精度），**不复刻**
  桩——理由更正为：桩在数学上精确等价于 `e^x`（唯一残差 ~1e-14，双精度
  量级），`Math.exp` 已是其精确等价物，复刻毫无意义。初稿"桩更差、
  复刻会引入误差"的理由（基于 21.22% 误数字）**已作废**。
- 0.0076% 残差 = 整数取整噪声下限（15 点取整值 ±0.5 的量化），非公式/
  桩层面缺陷，亦非 web 与 legacy 的口径差。
- 桩的 `FRNDINT`（round-to-even）与 JS `Math.round`（round-half-up）在
  B-scan 实际指数范围 [−0.2, 0] 内**无任何恰遇 .5 平局点**（12601 点
  网格扫描 0 命中），故取整平局行为差异对结果无影响（即使采用桩）。
- 此条关闭「exp 桩是否需 web 侧复刻」的潜在开放项；`verify-exp-stub.ts`
  （勘误版）作为回归脚本保留（PASS 退出码 0 = Math.exp 口径确认，精确桩
  与 Math.exp 单点差 1e-14 量级，15 点残差同为 0.0076%）。

### 8.20 SG/Wyckoff 对话框填表逻辑（§6 第 1 条）定案：机制 = `TFormWCF` + `FUN_0047b960`/`FUN_0047bb3c`（2026-10-19）

**开放项**（§6 第 1 条）：「选 SG 符号 + Wyckoff 位次如何填出坐标表」
本身未逆向，主管线只读 0x448 原子记录（occ,x,y,z,B）。

**裁决（调用图 + 指令级，2026-10-19）**：

1. **`TFormWCF` 是 Wyckoff 对话框**（DFM RTTI 实证：`.rsrc` 中
   `TFormWCF` 资源块紧邻字符串 `Wyckoff`，`CalcXRD.exe` 0x4736f4 附近）。
2. **三段字符串解析器的调用方定位**（`CalcXRD.exe` 全 `E8 rel32`
   扫描，pefile 实读）：
   - `FUN_0047b960`（解析 `(`…`)` → 3 double）被 **`0x47af4a`** 与
     **`0x47b4f7`** 调用；
   - `FUN_0047bb3c`（线性组合变体）被 **`0x47b602`** 调用。
     三个调用点均落在 `TFormWCF` 的方法区（0x47af00–0x47b6xx）。
3. **0x47b4f7 指令流**（`lea ESI,[EBP−0x28]; mov ECX,6; rep movsd`）
   = 把解析出的 3 个 double 复制进 6 double 栈块——即把一次解析结果
   填入 `.cord` 原子记录的坐标三元组（x,y,z）或晶格参数（a,b,c）槽位。
4. **用途定案**：`TFormWCF` 的 UI 文本框输入（晶格参数 / 角度 / 分数
   坐标三元组）经 `FUN_0047b960`（普通三段）或 `FUN_0047bb3c`（含
   `-x·c + y + z` 线性组合，用于 Wyckoff 等价坐标展开）解析为 3 个
   double，写入 `.cord` 原子记录（occ,x,y,z,B 中的坐标列）。

**结论 / 对项目的含义**：

- §6 第 1 条（SG/Wyckoff 对话框填表逻辑）**机制已定案**：填充管线
  = `TFormWCF` → `FUN_0047b960`/`FUN_0047bb3c` → `.cord` 原子记录，
  与强度计算管线（`FUN_004787f8`/`FUN_0047c6a0`）**完全独立**。
- 精确「哪个 DFM 控件对应哪一行 `.cord`」需 Delphi DFM 控件顺序
  映射（字段偏移 0x3B8 等），不影响 web 侧——web 的 `.cord` 解析
  （`crystal.ts` `parseCord`）与 legacy 的 `.cord` 字节格式已逐行
  对齐（§2.6 实证），对话框只是**输入生成**路径，非强度公式来源。
- 此条关闭 §6 第 1 条「SG 对话框填表逻辑未逆向」的知识边界登记
  （机制层面；控件级 DFM 顺序映射仍属低价值未知，不影响任何结论）。

### 8.21 FF.dat 缺失时 F′F″ 复选框处置定案：置灰（`Enabled:=False`），非取消勾选（2026-10-19）

**开放项**（§6 第 4 条）：装载器内 `[vtable+200]` 调用的语义（置灰 vs 取消勾选）未定。

**裁决（`FUN_0047907c` Ghidra 反编译 + §2 偏移表交叉）**：

`FUN_0047907c` 加载 `\FF.dat` 时：

1. 先调 `FileExists("\FF.dat")`（`FUN_004095d4`），返回 0（不存在）时：
   `(**(code **)(**(int **)(Self + 0x398) + 200))()`
   — `Self+0x398` 为 F′F″ 复选框对象指针（§2 偏移表 `0x398 = F′F″ 复选框`），
   `vtable+0xC8`（= 第 26 个虚方法，1-based）为 `SetEnabled`/`SetChecked` 类
   方法，与 `get_Checked`（`vtable+0xC4`，§2 表已登记）紧邻。
2. **仍继续读文件路径**（不 return）——即置灰后用户无法再勾选，但
   代码路径不中断（Delphi 惯用写法：置灰 + 后续 try-open 兜底）。

**定案**：FF.dat 缺失时，F′F″ 复选框被**置灰禁用**（`Enabled:=False`），
**不是**取消勾选（若取消勾选，应对 `get_Checked` 取反再 `set_Checked`，
代码中无此模式）。这与 §2.9「FF.dat 缺失 → 对 Self+0x398 执行禁用操作」
一致，本次字节级确认了 `[vtable+200]` 即禁用调用，§6 第 4 条关闭。

**web 侧对照**：`dispersion.ts` `hasDispersion(λ)` 返回 `false` 时 UI 置灰
F′F″ 复选框（`SettingsPanel.tsx`），与 legacy 行为一致；`supported=false`
语义 = 「该 λ 无数据，复选框不可用」，对应 legacy 的 FF.dat 缺失置灰。

### 8.23 Po Single XRD "Invalid floating point operation" 崩溃定案：primitive 单质无系统消光 → arcsin 越界（legacy 缺陷，web 已防护）（2026-10-19）

**现象**：legacy `CalcXRD.exe` 打开 `samples/Po.cord`（primitive Pm-3m，1 原子 @ (0,0,0)，a=3.345）后点 Single XRD 立即报 "Invalid floating point operation" 运行时异常。

**根因分析（数值推演 + §2.6 枚举守卫字节）**：

1. **枚举上界**：`N = floor(2a/λ) = floor(2×3.345/1.54056) = 4`，h,k,l ∈ [−4..4]，最大 `|hkl|² = 48`。
2. **d < λ/2 项**：`d(4,4,4) = 3.345/√48 = 0.4828 Å < λ/2 = 0.7703 Å`，
   `sinθ = λ/(2d) = 1.595 > 1`，`arcsin(1.595)` **超出定义域** → FPU 异常。
3. **legacy 守卫不足**：`FUN_004780b4` 枚举时的过滤条件是
   `λ/(2·fVar50) < d(hkl)`（fVar50 为 `FUN_004029dc()` 返回值，
   0x4787e4 常量 = 2.0f），**只过滤 2θ>180° 的项**；对 d 略小于 λ/2
   但 2θ<180° 的项不过滤。Po 因 primitive 无系统消光，所有 hkl 的
   `|F|² = f(Po)² > 0`，高 N 项直达 `arcsin` 分支。
4. **Al (FCC 225) 不崩的原因**：FCC parity 消光使高 N 奇和 hkl `|F|²≈0`，
   被 0.01 阈值（§8.11）过滤后才到 arcsin；Po 无此保护。
5. **web 引擎现状**（`single_xrd.ts:144-146`）：
   `if (sinTheta > 1) { continue; }` —— 已做 `d ≥ λ/2` 预过滤，
   实跑 Po 正常返回 170 行（N=1: 100000，N=4: 12348，N=5: 8239），无崩溃。

**定案**：
- 这是 **legacy 程序自身的缺陷**（primitive 单质 + CuKα1 路径未做
  `d ≥ λ/2` 预过滤，arcsin 越界触发 FPU 异常），非公式/参数错误。
- **web 侧无需改动**：`sinTheta > 1` 守卫已覆盖此情形，行为比 legacy 稳健。
- **§8.16 Po 21.2% 残差闭合路径关闭**：legacy 无法对 `samples/Po.cord`
  复现 single 表（程序自身崩溃），（已删除的 `ref-temp` 目录中的）Po-221 存档（来路不明，
  用户已确认 ref-temp 目录可删，目录已删除）**无合法复现路径**，维持"归因 B 值
  不匹配（≈1.55 vs 1.0）、公式层面自洽 0.0000%"的当前结论，不再追求
  逐值闭合。
- 登记至缺陷簿（`DATA-REFERENCE.md` #17 新增）。
